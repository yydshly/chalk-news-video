## 7. Existing ffmpeg Path

### 7.1 ffmpeg in `src/export_video.py`

The only ffmpeg usage is in the video export pipeline:

**Frame capture (PNG sequence):**
- Playwright navigates to `animation.html` via local HTTP server
- Waits 10s for `window.__ANIMATION_READY__`
- Gets total duration via `window.__getTotalDuration__()` (fallback: 60s)
- For each frame: calls `window.__setTime__(t)`, waits 15ms, `page.screenshot()` → PNG

**Encoding:**
```
ffmpeg -framerate 30 -i frame_%05d.png
  -c:v libx264 -pix_fmt yuv420p
  -vf scale=1280:720
  -movflags +faststart
  video_only.mp4
```

**Audio muxing (if WAV/MP3 provided):**
```
ffmpeg -i video_only.mp4 -i audio.wav
  -c:v copy -c:a aac -shortest
  output.mp4
```

**Requires:**
- `playwright` (Chromium headless)
- `ffmpeg` in PATH
- `window.__setTime__(t)` and `window.__getTotalDuration__()` APIs in the HTML

### 7.2 ffprobe usage

`ffprobe` is called after muxing to verify output duration:
```
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 output.mp4
```

## 9. Can CP38.1 Fixed Stage HTML Reuse Existing Export Path?

**Answer: No — not directly. Multiple incompatibilities.**

### 9.1 Incompatibility 1: HTML generator location

| Aspect | Existing pipeline | CP38.1 breaking_news_v1 |
|---|---|---|
| Generator location | `src/render_html.py` (Python) | `web/app.js` (browser JS) |
| Template | `renderer/template.html` (Jinja2) | Inline JS template string |
| Canvas | 1280×720 (16:9) | 9:16 vertical |
| Animation control | `window.__setTime__(t)` | CSS `animation-delay` only |

The `renderBreakingNewsStageEpisodeHtml()` function cannot be called from `src/pipeline.py` — it's in the frontend bundle, not importable from Python.

### 9.2 Incompatibility 2: Animation control APIs

The existing `export_video.py` relies on:
- `window.__getTotalDuration__()` — returns total animation duration
- `window.__setTime__(t)` — seeks to time `t` in the animation

The CP38.1 `breaking_news_v1` HTML:
- Uses pure CSS `animation-delay` for timing — no JS time control
- Has no `__getTotalDuration__` or `__setTime__` functions
- `stage-shot-meta` div has timing data but no JS API to consume it

**Workaround possibility:** A Playwright adapter could read `stage-shot-meta`, extract timing, and use CSS animation `currentTime` polyfill or simply take screenshots at fixed intervals. But this is non-trivial.

### 9.3 Incompatibility 3: Canvas size

- Existing pipeline: 1280×720 (16:9)
- CP38.1 breaking_news_v1: 9:16 (vertical)

`export_video.py` does accept `width`/`height` params, so this is the **least critical** issue.

### 9.4 Incompatibility 4: No server-side export endpoint for episode contracts

The `/api/episode/mock-html` (CP31) saves HTML but doesn't trigger export. There's no endpoint that:
1. Accepts an episode contract (or HTML string)
2. Triggers `export_video.export_video()`
3. Returns an MP4

## 10. Recommended Integration Strategy

### Path A (if reusing existing Playwright+ffmpeg pipeline): Adapter Layer

```
CP38.1 episode contract
  → new Python endpoint POST /api/episode/export
  → call src/render_episode_html.py (port of renderBreakingNewsStageEpisodeHtml to Python)
    OR read saved episode HTML from outputs/episode_previews/
  → write temporary animation.html
  → add window.__getTotalDuration__() and window.__setTime__() shim
  → call export_video.export_video() with 9:16 viewport
  → save output.mp4 to outputs/jobs/{job_id}/
```

**Required adapters:**
1. **Python port of `renderBreakingNewsStageEpisodeHtml()`** — move the HTML generation logic from `web/app.js` to `src/render_episode_html.py` so it can run server-side
2. **Timing shim** — add `window.__getTotalDuration__()` and `window.__setTime__()` to the generated HTML so Playwright can seek (alternatively: use fixed-interval screenshot approach without seeking)
3. **Episode export endpoint** — `POST /api/episode/export` that accepts episode contract + optional audio, runs render + export
4. **Viewport config** — pass 9:16 dimensions to Playwright (e.g., 720×1280 instead of 1280×720)

### Path B (if building Remotion path in future)

```
episode_template_v1 contract
  → Remotion Composition (Timeline component)
  → renderMedia() → MP4
```

**Current blockers for Path B:**
- No Remotion installed
- No Remotion config
- No `src/Root.tsx`
- Episode contract → Remotion props mapping would need significant work
